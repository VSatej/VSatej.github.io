The goal of this experiment is to simulate a CPU with a two-level cache hierarchy using gem5.

We will configure:

- An out-of-order CPU (DerivO3CPU).
- Separate L1 Instruction Cache and L1 Data Cache.
- A unified L2 Cache.
- A main memory controller (DDR3).
- A simple benchmark program.

We will then examine cache statistics and understand how cache size and latency affect performance.

## 3. Understanding the Components

### CPU

We use `DerivO3CPU`, which represents an out-of-order CPU model.

Out-of-order execution allows the processor to execute independent instructions without strictly following their original program order.

### L1 Instruction Cache

The L1 instruction cache stores recently accessed instructions.

When the CPU fetches an instruction, it first checks this cache.

### L1 Data Cache

The L1 data cache stores recently accessed data.

When the CPU loads or stores data, it accesses this cache.

### L2 Cache

L2 is a unified cache shared by instruction and data requests.

If the required data is not found in L1, the request can be forwarded to L2.

### Main Memory

If the requested data is not found in the cache hierarchy, the request eventually reaches main memory.

Accessing DRAM generally takes much longer than accessing cache.

## 4. Create the Simulation Configuration

Create a file named:

`cache_test.py`

The following is an illustrative classic-cache configuration. It uses gem5's Python configuration API.

```python
import m5
from m5.objects import *

# --------------------------------------------------
# 1. Create the system
# --------------------------------------------------

system = System()

system.clk_domain = SrcClockDomain()
system.clk_domain.clock = "2GHz"
system.clk_domain.voltage_domain = VoltageDomain()

system.mem_mode = "timing"
system.mem_ranges = [AddrRange("512MB")]

# --------------------------------------------------
# 2. Configure CPU
# --------------------------------------------------

system.cpu = DerivO3CPU()

# --------------------------------------------------
# 3. Configure L1 Instruction Cache
# --------------------------------------------------

class L1ICache(Cache):
    size = "16kB"
    assoc = 2
    tag_latency = 2
    data_latency = 2
    response_latency = 2
    mshrs = 4
    tgts_per_mshr = 20

# --------------------------------------------------
# 4. Configure L1 Data Cache
# --------------------------------------------------

class L1DCache(Cache):
    size = "16kB"
    assoc = 2
    tag_latency = 2
    data_latency = 2
    response_latency = 2
    mshrs = 4
    tgts_per_mshr = 20

# --------------------------------------------------
# 5. Configure L2 Cache
# --------------------------------------------------

class L2Cache(Cache):
    size = "256kB"
    assoc = 8
    tag_latency = 10
    data_latency = 10
    response_latency = 10
    mshrs = 16
    tgts_per_mshr = 20

# --------------------------------------------------
# 6. Instantiate caches
# --------------------------------------------------

system.cpu.icache = L1ICache()
system.cpu.dcache = L1DCache()

system.l2cache = L2Cache()

# --------------------------------------------------
# 7. Configure buses
# --------------------------------------------------

system.l2bus = L2XBar()
system.membus = SystemXBar()

# Connect L1 caches to L2 bus
system.cpu.icache.mem_side = system.l2bus.cpu_side_ports
system.cpu.dcache.mem_side = system.l2bus.cpu_side_ports

# Connect L2 cache to L2 bus and memory bus
system.l2cache.cpu_side = system.l2bus.mem_side_ports
system.l2cache.mem_side = system.membus.cpu_side_ports

# --------------------------------------------------
# 8. Connect CPU ports
# --------------------------------------------------

system.cpu.icache.cpu_side = system.cpu.icache_port
system.cpu.dcache.cpu_side = system.cpu.dcache_port

# --------------------------------------------------
# 9. Configure memory
# --------------------------------------------------

system.mem_ctrl = MemCtrl()
system.mem_ctrl.dram = DDR3_1600_8x8()
system.mem_ctrl.dram.range = system.mem_ranges[0]

system.mem_ctrl.port = system.membus.mem_side_ports

# --------------------------------------------------
# 10. Configure system port
# --------------------------------------------------

system.system_port = system.membus.cpu_side_ports

# --------------------------------------------------
# 11. Configure workload
# --------------------------------------------------

binary = "/path/to/arm64/benchmark"

system.workload = SEWorkload.init_compatible(binary)

process = Process()
process.cmd = [binary]

system.cpu.workload = process
system.cpu.createThreads()

# --------------------------------------------------
# 12. Instantiate and simulate
# --------------------------------------------------

root = Root(full_system=False, system=system)

m5.instantiate()

print("Starting gem5 simulation...")

exit_event = m5.simulate()

print("Simulation finished!")
print("Exit cause:", exit_event.getCause())

m5.stats.dump()
```

### Cache hit and miss

**Cache hit:** The requested data is found in the cache.

**Cache miss:** The requested data is not found in the cache, so the request must be serviced by a lower cache level or memory.

A lower miss rate generally means fewer requests need to go to slower memory levels.

### Expected observations

A larger L2 cache may reduce the number of memory accesses if the workload has sufficient data reuse.

However, a larger cache does not always improve performance. The result depends on the workload, access patterns, cache latency and other architectural parameters.

## 8. Key Takeaways

Through this experiment, we learn:

1. L1 instruction and data caches serve different purposes.
2. L2 is a unified cache shared by both L1 caches.
3. Cache misses can cause accesses to slower memory.
4. Cache size and associativity influence hit and miss behaviour.
5. gem5 allows us to experiment with different CPU and memory configurations.

- Investigating memory latency and bandwidth.
